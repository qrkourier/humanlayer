Initial implementation: the Electric proxy reads public WorkOS JWKS configuration
without constructing a privileged management SDK client. Only its client ID is
required. This is an independently reviewable prerequisite, not a generic OIDC
adapter or a complete self-hosting mode. JWT verification and ACL behavior remain
unchanged. The API still requires WorkOS; provider-neutral claims, local
memberships, application sessions and worker credentials remain planned work.

Next implementation slice: isolate authentication trust/claims mapping from the
WorkOS membership directory in both API and sync. Keep signature/issuer/audience
validation and the application authorization context consistent; do not wire an
external OIDC token straight into WorkOS-specific organization claims. Follow the
six release gates in the design before claiming a self-hosted release.
